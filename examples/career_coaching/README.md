# Career coaching

Which system prompt makes a small model give better career advice? There is no gold answer
to "I've been passed over for promotion twice, what's holding me back?", so the metric is a
pairwise AI judge. This example has two parts: a hand-written judge, and the same judge
calibrated against preference labels.

## Part one: a hand-written judge

`judge.py` defines `PairwiseJudge`, an ordinary `metric(expected, predicted)`. The seed prompt
answers every question once and those answers become the targets; the judge sees the question
and both answers in both orderings and returns one of `A_BETTER`, `B_BETTER`, `BOTH_GOOD`,
`BOTH_BAD`, constrained to that set by a JSON schema on the server. Each ordering scores 1 for a
win, 0 for a loss and 0.5 for either tie label, and the two are averaged, so a question can
score 0, 0.25, 0.5, 0.75 or 1. The judge model is larger than the model being optimised;
judging with the same model measures self-preference.

```bash
python -m examples.career_coaching.run \
    --model llama-3.1-8b-instruct --base-url http://127.0.0.1:8124/v1 \
    --judge-model qwen2.5-72b-instruct-awq --judge-base-url http://127.0.0.1:8123/v1 \
    --optimizer GEPA --optimizer-kwargs '{"max_metric_calls": 120}' \
    --output runs/coaching/gepa
```

Forty questions, 16 / 12 / 12 split, Llama-3.1-8B optimised, Qwen2.5-72B judging:

| Optimiser | Final val / test | Verdicts that were ties |
|---|---|---|
| DSPy GEPA, 120 calls | 0.500 / 0.500, kept seed | 451 of 464 |
| DSPy MIPROv2 | 0.500 / 0.500, kept seed | 229 of 232 |
| TextGrad TGD | 0.521 / 0.500 | 278 of 280 |

The judge called almost every comparison `BOTH_GOOD`. Neither DSPy optimiser found a candidate
that beat the seed; TextGrad's 0.521 on validation came from a single decisive verdict and
selected a prompt that reads as a reply to one training question, so its selection was noise
and the prompt is not reusable. The judge does tell bad from worse (a deliberately bad answer
scored 0.0 against the seed), but it cannot rank two competent answers. Two live failures shaped
it: the 72B appended prose after its label until a schema constrained the output, and then hit
the schema's string cap and emitted blank lines until vLLM's whitespace pattern was set.

## Part two: calibrate the judge, then optimise

`preference_data.py` builds a synthetic preference set, since no human coaching votes exist:
the 40 questions above plus 120 generated by the 72B across ten scenarios; a strong 72B answer
per question paired with degraded copies of itself (specifics removed, off-topic, truncated,
padded, unethical suggestion added), labelled with the intended ordering; and natural pairs
(8B seed answer against the 72B answer, and against an 8B bare-prompt answer) labelled by the
72B reasoning step by step over three seeds and both orderings, strict majority, tie otherwise.
The committee is a proxy for human votes, not a human. Splits are by question, 55 / 25 / 25
for the judge and 27 / 14 / 14 for response optimisation, disjoint.

```bash
python -m examples.career_coaching.calibrate_judge \
    --model qwen2.5-72b-instruct-awq --base-url http://127.0.0.1:8123/v1 \
    --small-model llama-3.1-8b-instruct --small-base-url http://127.0.0.1:8124/v1 \
    --output runs/coaching_preference/stage1-gepa

python -m examples.career_coaching.optimize_with_judge \
    --judge-run runs/coaching_preference/stage1-gepa --judge best \
    --judge-model qwen2.5-72b-instruct-awq --judge-base-url http://127.0.0.1:8123/v1 \
    --model llama-3.1-8b-instruct --base-url http://127.0.0.1:8124/v1 \
    --output runs/coaching_preference/stage2-gepa-best-judge
```

Stage 1, agreement of the label-only 72B judge with the labels on 200 held-out rows:

| | Validation | Test | Committee pairs | Constructed pairs | Position consistency |
|---|---|---|---|---|---|
| seed judge | 0.665 | 0.630 | 0.659 | 0.622 | 0.63 |
| GEPA-calibrated | 0.695 | 0.630 | 0.750 | 0.596 | 0.81 |

Calibration made the judge more consistent and closer to the committee without improving
overall held-out agreement: it gained on committee pairs and lost on the constructed ones,
mostly by calling the padded and the specifics-removed rewrites ties more often (it never
preferred them). The committee preferred the 8B's longer answers over the 72B's concise ones
117 to 29, so a length preference is a plausible part of what was learned, though length is
confounded with model and prompt. 236 of the 1,920 committee votes were invalid and majorities
are over valid votes. Twenty-five question groups, one seed.

Stage 2, GEPA optimising the 8B's coaching prompt on 14 held-out questions. Each cell is a
selected prompt's answers scored against the same seed-prompt incumbents by one judge, not a
head-to-head between the two prompts:

| Selected with | Scored by calibrated judge | Scored by seed judge |
|---|---|---|
| calibrated judge | 0.679 | 0.607 |
| seed judge | 0.696 | 0.661 |

Both judges gave GEPA a gradient and both prompts score well above the 0.5 seed under either
scorer; in this single run the prompt selected with the calibrated judge shows no test-score
advantage. Part one's judges tied on 97% of verdicts, these on 34% (calibrated) and 27% (seed)
over their whole runs; the label set, the questions and the answer lengths all changed between
the parts, so that difference is an observation rather than an explanation. Exploratory
throughout: 14 questions, one seed, synthetic labels.
